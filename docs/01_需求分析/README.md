# 需求分析

## 项目愿景

构建一个 AI 驱动的故事知识库，实现两个方向：

```
方向一（分析）：任意文字 → 结构化知识库
方向二（创作）：想法/种子 → AI 协作 → 小说输出
```

两个方向共享同一套数据模型（人物卡、设定卡、关系图）。

## Phase 1 需求（最小 Demo）

### 用户故事

> 作为一个读者，我希望能把一段文字丢进系统，
> 自动得到里面的人物卡片和关系图谱，
> 在 Obsidian 里能直观看到谁和谁有什么关系。

### 功能清单

| # | 功能 | 优先级 | 状态 |
|---|------|--------|------|
| 1 | 读取 txt 文件 | P0 | 待开发 |
| 2 | 调用 DeepSeek 分析文本 | P0 | 待开发 |
| 3 | 提取人物信息（姓名/身份/性格/关系） | P0 | 待开发 |
| 4 | 提取设定信息（地点/势力/体系） | P1 | 待开发 |
| 5 | 生成 Obsidian 人物卡片（.md） | P0 | 待开发 |
| 6 | 生成 Obsidian 设定卡片（.md） | P1 | 待开发 |
| 7 | 生成作品索引 _index.md | P1 | 待开发 |
| 8 | Graph View 显示关系连线 | P0 | 待开发 |

### 验收标准

- [ ] 输入一段 ≥ 500 字的文本，自动生成 ≥ 3 个人物卡片
- [ ] 人物卡片中包含 wikilink 格式的人际关系
- [ ] 用 Obsidian 打开 vault，Graph View 能看到节点和连线
- [ ] 点击 wikilink 能正确跳转到目标人物卡片

## Phase 2 需求（扩展，规划中）

- 章节切分 + 逐章分析
- 长文本分块处理
- epub/pdf 格式支持
- 事件卡片、时间线
- 多本书管理

## Phase 3 需求（创作方向，远期）

- 种子输入 → AI 提问协作 → 世界观构建
- 人物卡 + 设定 → AI 驱动人物推演
- 推演结果 → 章节化小说输出
