# Story Wiki 部署文档

> 适用版本：v0.13.0+（含 SQLite 元数据层、上传分析、最小鉴权）

## 一、部署方式总览

| 方式 | 适用场景 | 上手成本 |
|------|----------|----------|
| 启动脚本（start.bat / start.sh） | 本机自用、演示 | 最低 |
| Docker Compose | 服务器部署、长期运行 | 低 |
| 手动 pip + uvicorn | 定制环境、开发调试 | 中 |

三种方式跑的都是同一个 FastAPI 应用（`web.app:app`），数据全部落盘在项目 `data/` 目录。

## 二、前置条件

- Python ≥ 3.13（脚本/手动方式），或 Docker 24+
- 一个 OpenAI 兼容 API Key（分析功能必需，浏览功能不需要）
- 端口 8000 未被占用

## 三、方式 A：启动脚本（推荐本机使用）

```powershell
# Windows
.\start.bat
```

```bash
# Linux / macOS
chmod +x start.sh
./start.sh
```

脚本自动完成：创建 .venv → 安装 `.[web,formats,office]` → 构建 SQLite 索引 → 启动服务。
浏览器打开 http://127.0.0.1:8000。

## 四、方式 B：Docker Compose（推荐服务器使用）

```bash
# 1. 准备配置
cp .env.example .env      # 填入 STORY_WIKI_API_KEY

# 2. 可选：设置访问密码（上传/分析接口需要登录）
export STORY_WIKI_PASSWORD=your_password   # Windows: set STORY_WIKI_PASSWORD=...

# 3. 构建并启动
docker compose up -d --build

# 4. 查看日志 / 停止
docker compose logs -f
docker compose down
```

服务启动后监听 `8000` 端口，数据持久化通过两个挂载卷：

| 宿主机路径 | 容器路径 | 内容 |
|---|---|---|
| `./data` | `/app/data` | 上传的原文（data/input）、分析产物（data/output）、SQLite 库（data/wiki.db） |
| `./vault` | `/app/vault` | CLI 分析默认输出目录（可选） |

> 备份 = 备份 `data/` 目录，一个 tar 包搞定。

## 五、方式 C：手动部署

```bash
python -m pip install -e ".[web,formats,office]"
python -m src.indexer --rebuild        # 首次构建全文索引
uvicorn web.app:app --host 0.0.0.0 --port 8000 --workers 1
```

> `--workers` 保持 1：后台分析任务跑在进程内单并发队列，多 worker 会导致任务状态分散。

## 六、环境变量

| 变量 | 必填 | 说明 |
|------|------|------|
| `STORY_WIKI_API_KEY` | 分析必需 | OpenAI 兼容 API Key |
| `STORY_WIKI_BASE_URL` | 否 | API 地址，默认小米 MiMo |
| `STORY_WIKI_MODEL` | 否 | 模型名，默认 mimo-v2.5 |
| `STORY_WIKI_PASSWORD` | 否 | Web 访问密码；**不设置 = 鉴权关闭（仅建议本机使用）** |
| `STORY_WIKI_SECRET` | 否 | 会话签名密钥；多实例部署时显式设置 |
| `STORY_WIKI_VAULT` | 否 | CLI 分析输出目录，默认 `./vault` |

## 七、鉴权说明

- 设置 `STORY_WIKI_PASSWORD` 后：上传（`POST /api/documents`）、发起分析（`POST /api/analyze`）需要登录，概览类 GET 接口保持公开
- 登录地址：`/login`；会话为 HMAC 签名 cookie（httpOnly），有效期 7 天
- 生产环境务必设置密码，并将 8000 端口置于反向代理（Nginx/Caddy）与 HTTPS 之后

## 八、Nginx 反向代理示例

```nginx
server {
    listen 443 ssl;
    server_name wiki.example.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        # 上传 100MB 文档需要的配置
        client_max_body_size 110m;
        proxy_read_timeout 300s;
    }
}
```

## 九、健康检查与运维

```bash
# 存活检查
curl http://127.0.0.1:8000/api/books

# 查看索引统计（各作品实体数）
docker compose exec story-wiki python -m src.indexer --stats

# 重建全文索引（md 卡片被手动改动后）
docker compose exec story-wiki python -m src.indexer --rebuild
```

镜像内置 HEALTHCHECK（`/api/books`），`docker ps` 可直接看到健康状态。

## 十、常见问题

**Q：上传 docx 报"需要 python-docx"？**
镜像和启动脚本已包含。手动部署漏装了：`pip install "story-wiki[office]"`。

**Q：分析任务一直 pending？**
任务单并发排队，前一个没跑完就排队。查看日志：`docker compose logs -f`。

**Q：搜索没有结果？**
生成新书后索引会自动增量入库；若是老数据（v0.12 之前生成），跑一次 `python -m src.indexer --rebuild`。

**Q：重启后登录会话失效？**
未设置 `STORY_WIKI_SECRET` 时密钥从密码派生，密码不变会话就有效；若需跨实例共享会话，显式设置相同的 `STORY_WIKI_SECRET`。
